## 1. 远程工作区（Remote-SSH）

### 1.1 三种方案不要混

用户一开始说「本机临时目录 + 远端注入 + 本机显示流」，听起来像工作区同步（方案 C）。对齐后做的是 **B**：本机只是显示器，worker 在远端拼上下文、调 API、跑工具。A 是 `ssh -t` 整屏转发，这版不做。

代价：密钥必须出现在调 API 的那一侧（远端 worker）。后来改成会话注入，而不是长期写进远端 `~/.socode`。

### 1.2 不要用 `ssh -t` 跑协议

B 的 stdout 必须是 JSON-RPC NDJSON。分配了 TTY 之后 MOTD、prompt、颜色会和协议抢同一条管子。全程 `-T`，worker 用 `exec node … --stdio`。

### 1.3 `ControlMaster=auto` 第一次是空连接

复用 SSH 时如果还没有 master，`auto` 会开一条马上退出的连接，探测脚本看起来「成功」但 stdout 里没有 `SOCODE_PROBE_V1`。做法：先 `-fN` + `ControlMaster=yes` 握手，之后业务命令 `ControlMaster=no` 走已有 mux。

### 1.4 远端 login shell 会拆掉多行 `-c`

`ssh host -- bash -c $'line1\nline2'` 经常被登录壳按空白切开，探测标记丢失，后面一直等握手。多行脚本先 **base64 进临时文件** 再 `bash --noprofile --norc`（`wrapRemoteScript`）。worker 启动必须是 **单行 `exec`**，stdin 留给 JSON-RPC，不能再套一层写文件的 bash。

### 1.5 密码登录不能占用 worker 的 stdin

密码走 `SSH_ASKPASS` + ControlMaster，不要 `ssh -t` 交互输入，也不要把密码塞进 `SendEnv`。公钥失败再回落到密码。非 TTY 才看 `SOCODE_SSH_PASSWORD`。口令只用于当场测试，不进 git。

### 1.6 不要从本机上传 Node 二进制

本机 scp 一份 ~45MB 的 Node 会让连接日志停很久，像卡死。对方网络通的话：探测已有 22+ → 否则远端 `curl`/`wget` 走 nodejs.org → npmmirror → 腾讯镜像，解压到 `~/.socode-server/node/`。

### 1.7 MOTD 会毁掉 JSON-RPC 缓冲区

第一版遇到非 JSON 行就清空整个 buffer，握手包如果和欢迎语粘在一起就被扔掉，表现为「Using cached runtime」之后再也没下文。正确做法：跳过坏行，保留后面的 JSON（`JsonRpcPeer.drain`）。

### 1.8 `node:test` 会把 IPC 环境传给 spawn 出来的 worker

`NODE_CHANNEL_FD` / `NODE_UNIQUE_ID` / `NODE_OPTIONS` 让打包后的 worker 以为自己还在测试跑器里，stdio 被占用，握手超时。`nodeWorkerEnv()` 必须剥掉再 `spawn`。

### 1.9 日志停住 ≠ 对方没网

远端下载 Node 的进度条刷 `#`，本机看起来像挂了。握手也要有「启动 worker / 等待握手」日志和 60s 超时；worker 异常退出要带 exit code，不要干等。

### 1.10 远端没有 Provider 时模型名是空白

状态行把空模型拼成 ` · medium · new`。没配模型时写 `未配置模型`，不要留一个空位。

### 1.11 工作区选择：Enter 不是进目录

第一次把 Enter 当成「选中并连接」，箭头没机会往下走。约定：`→` 进子目录，`←` 返回，Enter 第一次问「确定选择 X 为工作目录？」，再按一次才连。

### 1.12 Provider 注入不要进 tar / RPC / 远端 `~/.socode`

用户要「本机那份直接给远端，但断开前删掉」。不要：

- 打进 `socode-runtime` tar
- 放进 `initialize` 字段
- 覆盖对方 `~/.socode/providers.json`
- 把 `sk-` 写进 SSH 环境变量

要：scp 到 `~/.socode-server/session/providers.json`（`chmod 600`），worker 只带路径 `SOCODE_PROVIDER_STORE=…`。`finally` 里先杀 worker，再 `rm -f` 会话文件，再关 SSH。

### 1.13 `process.exit` 会跳过清理

远程 REPL 里 Ctrl+C 若直接 `process.exit(130)`，`attachRemoteWorker` 的 `finally` 不会跑，会话密钥留在远端。改成抛 `ForcedQuitError`，让 wipe + `session.close()` 跑完再退出。

### 1.14 `listRemoteWorkspaces(session, log)` 不能把 logger 当路径

重构后第二个参数改成 `{ dir, log }`。若仍把 logger 对象当 `dir` 传进去，列目录脚本会得到 `[object Object]`。

### 1.15 打包 worker 读的是 `dist/`，不是 `src/`

本机 `tsx src/index.ts` 已支持 `SOCODE_PROVIDER_STORE`，但 scp 过去的是 `dist/`。改 `provider.ts` 之后不 `npm run build`，远端 worker 仍读 `~/.socode/providers.json`，表现为「注入成功、模型还是空的」。

### 1.16 worker 入口不要用顶层 `await`

`bin/worker-entry.mjs` 里 `await runWorkerStdio(...)` 会一直挂到 stdin 关掉。Node 22 把它当成 **unsettled top-level await**，往 stderr 打一行警告，Remote-SSH 把 worker stderr 接到本机后就会插进 TUI 中间。入口改成 `main().catch(...)`，不要顶层 await。

### 1.17 `/root` 是 root 的家，不是 `/etc`

沙箱曾把整棵 `/root/` 放进禁写目录。用 root 登录远端、工作区在 `/root/server/...` 时，bash 的 cwd 也在 `/root` 下，连 `echo` 都报「拒绝访问受保护路径: /root」。应只拦 `/root/.ssh`、`/root/.socode` 这类密钥路径，不要封整棵家目录。

## 2. Provider 与密钥文件

### 2.1 工作区 `.env` 和用户级 store 不是一回事

早期密钥在项目 `.env` + Postgres。后来对话、undo、审计绑 **工作区** `.socode/`，Provider 和 harness 默认在 **用户级** `~/.socode/providers.json`。`.env` 只做一次性迁移，启动后再读会和「所有对话共用一份 Provider」打架。仓库里的 `.env` / `providers.json` 必须 gitignore。

### 2.2 `saveProvider` 会吞掉 cwd 的 `providers.json`

`readStore()` 在 `~/.socode/providers.json` 不存在时，会把 **当前工作区** 的 `providers.json` 迁进用户目录。测试里设了 `SOCODE_HOME=/tmp/…` 仍会触发：

1. 仓库里碰巧有一份真实 `providers.json`
2. `saveProvider({ api: "sk-home" })` 先 `readStore()`，把真实密钥迁进临时 HOME
3. 再把测试 Provider **追加** 进去
4. `providers[0].api` 变成真实 key，断言 `sk-home` 失败
5. 更糟：若 `SOCODE_HOME` 没设稳，可能写回用户真目录

`assert.match(/sk-home/)` 挡不住这种污染。约定：

- 设了 `SOCODE_HOME` 或 `SOCODE_PROVIDER_STORE` 时 **不要** 迁移 cwd
- 测试断言 `providers.length === 1`，不要只 match 子串
- `dumpProviderStore()` 给远端注入时走同一套 `readStore()`，避免测的是 A、连的是 B

远程 worker 若没注入文件、又去迁远端仓库里的 `providers.json`，会把对方项目密钥写进会话文件。所以 `SOCODE_PROVIDER_STORE` 一旦设置，缺失就当没有 Provider，不要回落到 cwd。

### 2.3 API Key 没有加密存储

当前就是用户目录里一份 JSON。不要假装有保险箱；也不要为了「方便」打进环境变量或 runtime 包。

## 3. 终端 UI

### 3.1 状态行被当成对话内容复读

输入行下面的 `deepseek-flash · medium · new` / `context 5%` 一旦写进 scrollback，空输入、空格、重绘都会再打一行。用户会觉得「我敲空格你复读」。状态行只能活在当前 prompt 的预留行里，不能 `console.log`。没对话时用 `new`，有标题再用会话名，不要预创建「创建会话名」。

### 3.2 思考块必须和正文分通道

`reasoning_content` / `<think>` 若混进 assistant `content`，Markdown 重绘会把斜体思考和正式回复叠在一起。思考只进 `thinking` 事件，暗色斜体，不入库为给模型的 assistant 正文。

### 3.3 差量重绘不要整段擦

按 token 用 `\\x1b[<n>A` 把整块思考擦掉重画，行数一估错就花屏。只重画最后一行 tail（Codex 那套 stable/tail）。

### 3.4 Ask 短预览不够

「每天当主力」过不了的原因之一：审批只给三行摘要。Ask 的 write/edit/delete 必须打完整 unified diff，再 `y/n/a`。

### 3.5 覆盖写文件不是 apply_patch

产品化对照里缺 `apply_patch`。socode 的 `edit` 是精确 snippet 替换 + 原子写，不是 git apply。不要对外宣传成 patch 工具；也不要再退回「整文件覆盖当编辑」。

### 3.6 沙箱「敏感路径」不能一律硬拒绝

git、工作区外的读写，用户明确要做时应当询问，而不是本地直接拒绝。密钥文件、`sudo`、`.env` / `providers.json` 仍硬拒绝。Long 的副作用走独立审批 LLM，不要把 Long 变成 Full。

### 3.7 会话不要进 Postgres，也不要进用户 home

第一周用 PostgreSQL 存对话。工作区一换，对话串台、依赖变重。后来改成 `工作区/.socode/sessions/`，空对话不落盘。`/setworkarea` 换的是仓库根，不是「同一份全局聊天」。

### 3.8 `/provider edit` 空输入是保留，不是清空

回车必须保留方括号里的当前值。多个 Provider 用方向键列表切，思考强度只许 `/effort` 改，避免编辑表单和 effort 两个入口打架。

## 4. 测试与打包

### 4.1 Cursor 沙箱里 `tsx` 会 EPERM

本仓库测试常用 `required_permissions: ["all"]`。失败时先看是不是沙箱，不要当成产品 bug 改代码。

### 4.2 真机验证不要把口令写进 repo

可以用用户提供的 SSH 口令测密码登录，但测试 fixture、提交、文档、日志里都只能留「密码登录成功」这类句子。`undefined/` 解压目录、runtime 缓存里的 `providers.json` 都要当事故现场清掉。

### 4.3 横幅标题变长会撑破窄框

`socode @ 0.1.2 presented by Tm-Ys` 比原来的 `socode` 长三十多列。`drawBox` 的宽度下限要按标题宽度算，否则顶边比左右竖线长，对不齐。
