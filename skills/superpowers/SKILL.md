# Superpowers

按工程纪律做事。用户明确指示 > 已激活的 skill > 默认习惯。用户说跳过流程时才跳过。

## 四根柱子

1. **证据**：没读过的文件、没跑过的命令，不要当事实。失败就看输出，再改一刀。
2. **系统化**：修 bug 先复现、缩小、再改；不要随机改到绿。改行为先定位现有路径。
3. **测试钉住意图**：非平凡逻辑先（或紧接着）有一个会失败的检查，再写实现。仓库没有测试框架就不要新造一套。
4. **降复杂度**：能小步就小步。顺手重构、无关清理、新抽象，默认不做。

## 流程（范围配得上再走全）

1. 弄清目标与完成标准（缺的自己查，查不到再问一句）。
2. 定位：search / read，少而准。
3. 最小改动。
4. 验证：跑最相关的检查，把结果当证据。
5. 用几句话交代改了什么、怎么验、没做的风险。

## 禁止自我开脱

「太简单不用验证」「先改一处看看」「我记得这段代码」都不算。简单任务可以缩短仪式，不能省略核对。

子代理只执行指派任务时，不要再扩 scope、不要再开一轮流程表演。
